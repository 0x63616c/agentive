# Agentive codebase audit — 2026-09-14

## Scope and method

This audit covers the complete Agentive workspace after the five v1 tracer slices. It evaluates the repository against `docs/SPEC.md`, the Rust guidance in `AGENTS.md`, the public API contract, local and Temporal execution parity, provider/tool safety, packaging, and release automation.

Verification was performed with the pinned MSRV and stable Rust toolchains, all features and targets, doctests, rustdoc warnings-as-errors, mdBook tests/build, dependency policy, the feature-power-set, GitHub workflow linting, four real Temporal server scenarios, and one deliberately bounded live Codex subscription run.

## Health summary

The codebase is suitable for a pre-1.0 foundation release. Provider-facing effects are explicit and serializable, local and Temporal execution share the same state machine, tool schemas and callbacks fail closed, usage and limits are retained across attempts, and the public provider/tool seams are mockable. The remaining design debt is intentionally bounded to API evolution before 1.0 and future workflow-version migrations.

## Findings and dispositions

| ID | Severity | Finding | Disposition |
| --- | --- | --- | --- |
| H1 | High | Local error exits could leave a run pending or running. | Fixed: the run wrapper now finalizes every nonterminal error exactly once and tests assert terminal status and events. |
| H2 | High | Durable execution bypassed canonical history and provider-response validation. | Fixed: effect execution and commits share validation with local execution; forged effects and malformed outcomes are rejected. |
| H3 | High | Temporal could retry provider side effects without an idempotency contract. | Fixed: provider activities default to one attempt; the second attempt requires explicit durable-idempotency opt-in. |
| H4 | High | Temporal cancellation did not persist canonical cancelled state. | Fixed: cancellation commits `Cancelled`, updates the snapshot, and returns the canonical terminal result. |
| H5 | High | Codex silently ignored canonical context/output constraints. | Fixed: supported defaults are explicit and unsupported values fail before transport opens. |
| H6 | High | Codex runtime tools could broaden the tools authorized by a request. | Fixed: request descriptors and executable handles must match exactly. |
| H7 | High | Manual tool schemas were not compiled or required to be closed objects at registration. | Fixed: registration compiles schemas and enforces the canonical top-level contract. |
| H8 | High | Workflow fingerprints rejected changes without a historical migration registry. | Deferred: v1 has no released historical fingerprint to migrate. Before changing the first released fingerprint, add deterministic migration fixtures and version markers. |
| H9 | High | Restored durable state could replace worker-owned instruction fragments. | Fixed: workers recompute every core, agent, feature, and preserved run fragment and reject any mismatch before effects. |
| H10 | High | Temporal silently capped effects at 60 seconds when a run had no deadline. | Fixed: no-deadline runs use Temporal's required maximum persisted timeout; explicit deadlines still use their exact remaining duration. |
| H11 | High | The retry-composition test did not exercise activity redelivery. | Fixed: the real-server test kills a worker after the Agentive retry reaches upstream completion, redelivers the same effect, and proves the durable cache prevents a second retry sequence. |
| M1 | Medium | Codex erased model-safe tool error codes and messages. | Fixed: safe code/message are preserved while private sources remain hidden. |
| M2 | Medium | The Temporal release workflow assumed an installed Temporal CLI. | Fixed: CI installs the official pinned CLI action/version. |
| M3 | Medium | Codex cancellation could hang during initialization or request setup. | Fixed: every setup phase is cancellation-aware and bounded; a stalled-init test verifies cleanup. |
| M4 | Medium | Public `Message` fields permit invalid role-dependent combinations and history crossing. | Mitigated: complete role-shape and ordered call/result validation runs at state and execution boundaries. Role-specific private representations remain a pre-1.0 API-deepening candidate. |
| M5 | Medium | Durable callers could forge tool policies independently of the worker. | Fixed: `Agent::prepare_state` binds the plan and workers require exact policy equality before effects. |
| M6 | Medium | A completed Temporal handle could time out when observed after result retrieval. | Fixed: handles retain the terminal snapshot/result for late observers. |
| M7 | Medium | Published crates omitted referenced license files. | Fixed: both license files are included in every package and package manifests were inspected. |
| M8 | Medium | Delegated children reset the parent tree's parallel-tool limit. | Fixed: the limit is inherited; a concurrency-probe test proves a parent limit of one remains one in the child. |
| M9 | Medium | Late cancel/fail calls could overwrite an existing terminal state. | Fixed: terminal transitions are first-writer-wins and serialization coverage preserves the invariant. |
| L1 | Low | Several implementation files are moderately large. | Accepted for now: responsibilities are already split into domain modules; further mechanical splitting would add navigation without deepening an interface. Reassess when a file gains a second reason to change. |
