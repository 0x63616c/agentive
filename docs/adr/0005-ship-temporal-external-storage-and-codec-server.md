# Ship Temporal External Storage and a Codec Server outside the agent interface

The SDK distribution will include always-on Temporal External Storage, one local/shared-filesystem Storage Driver, and a storage-aware Codec Server library, all configured through Temporal clients and workers. S3-compatible and other object-store drivers are deferred behind the same `StorageDriver` contract. Every codec-capable Temporal payload follows the same external-reference path. Agent builders, canonical messages, workflow inputs, and activities remain unaware of payload references and use ordinary typed Rust values. Storage Drivers have validated logical identities; the registry selects exactly one default writer while retaining as many readers as are needed for old references. This permits storage migration without rewriting immutable Workflow History. The single-store API hides the registry and its internal default identity. Stored payload objects use opaque non-content-derived identities, are immutable, and are verified against the length and cryptographic checksum captured in each reference. Idempotent retries may confirm an identical existing object but can never overwrite it. The SDK never deletes payloads automatically or attempts to infer reachability from Temporal; operators configure storage retention to outlive relevant Workflow History and archives. Payload Codecs execute in explicit declaration order while encoding and exact reverse order while decoding. V1 includes compression but deliberately omits a first-party authenticated-encryption codec and key-management system; applications may add such a codec through the same chain. Applications mount and operate the supplied Codec Server handler; the SDK does not ship a standalone server executable. This keeps large-payload policy at the durable-transport seam while making the operationally complete feature easy to adopt instead of requiring every agent SDK user to rebuild the claim-check and UI-access stack.
